## 1. 登录与个人中心

### 1.1 登录

1. 打开后台地址，进入登录页（BRA · 管理后台）。
2. 填 **用户名**、**密码**，再完成中间的图形验证码。
3. 点 **登录**。成功后自动进入首页。

如果你的账号绑定了 **动态验证码**（见 [1.3](#13-个人中心)），登录是**两步**的：密码对了之后
用户名/密码下方会多出一格 **6 位动态验证码**，填上验证器 App 里当前那 6 位数字再点一次 **登录**。
码 30 秒一变，提示 **动态验证码错误** 就等下一格数字再试。第一次登录时密码错了不会看到这一格 ——
后端在密码验过之后才会告诉前端「这个账号开了验证码」，否则谁都能拿账号名探出「谁开了验证码」。

页面底部有一行**站点信息**：当前版本号、版权与项目地址（点击在新标签打开仓库）；
登录后侧边栏底部也有同一行（侧边栏折叠时隐藏）。报障时附上版本号最省事。
版权文字与项目地址都可以在「系统配置」里修改，见 [3.10](#310-系统配置systemconfig)。

关于验证码，有三点值得知道：

- 验证码有**点击、旋转、滑块**三种，每次随机出现一种，提示文字跟着类型走：
  「按顺序点击图中出现的文字/图案」/「拖动图片，把它转正」/「拖动拼图块，补上图中的缺口」。
- 点错了可以点 **撤销**，看不清可以点 **换一张**。
- 验证码是**一次性的**：登录失败后验证码会刷新，需要重新做一遍，不是系统在刁难你。

登录失败的提示对照：

| 界面提示 | 含义 |
| --- | --- |
| 用户名和密码不能为空 | 有一项没填 |
| 用户名或密码错误 | 账号不存在与密码错误共用这一句（不给探测账号是否存在的机会） |
| 验证码错误 | 重做一次验证码即可；**答错验证码不累计失败次数** |
| 需要动态验证码 | 账号绑了动态验证码，密码已经对：填验证器 App 上的 6 位码（见 [1.3](#13-个人中心)） |
| 动态验证码错误 | 码不对或已过期（30 秒一变），等下一格数字再试；**码错和密码错一样累计失败次数** |
| 账号已被禁用 | 账号被停用了，联系超级管理员把它改回「启用」 |
| 尝试过于频繁，请 N 分钟后再试 | 失败次数触发了限流，见 [5.2](#52-账号被锁了什么时候能再登) |

默认策略：同一账号或同一来源 IP 累计 **5** 次密码错误，锁 **10** 分钟。验证码答错不算次数。

### 1.2 顶栏

从左到右：面包屑（当前位置）、**切换语言**（简体中文 / English）、**切换明暗主题**、未读公告铃铛、头像菜单。

- 语言与主题是**本机偏好**，存在你这台电脑的浏览器里，不跟着账号走 —— 换台电脑要重新设一次。
- 语言初始跟随浏览器，主题初始跟随系统的深浅色设置。改了之后就一直用你选的那个。
- 头像菜单两项：**个人中心**、**退出登录**。

### 1.3 个人中心

**维护资料**：昵称、邮箱、手机号等，改完点 **保存资料**，只影响你自己的资料，不影响任何人的登录状态（邮箱、手机号在库里是加密存放的）。

**更换头像**：

- 只收 **PNG / JPEG** 两种格式。
- 大小上限 **512 KB**；图片超过 512 KB 时浏览器会先自动压缩（最长边压到 512 像素、JPEG 质量逐档下调），压完仍然超过 512 KB 才会提示换一张小图。
- 上传时显示进度（头像上传中），成功后顶栏头像立即更新。

**修改密码**：填 **原密码**、**新密码**（至少 8 位，且需包含字母、数字、符号中的至少两类）、**确认新密码**。改完之后**所有设备（包括当前这台）立即下线**，需要重新登录 —— 这是有意的，多端同步不了密码变更，只能全部作废。改完记得用新密码登录。

**退出其他设备**：点一下并确认后，其他设备上的登录**立即失效**、需要重新登录；**当前这台设备保持登录**（后台会悄悄给你换一张新令牌，你不会被踢下线）。适合「电脑借给别人用过」「密码疑似泄露」这类场景。

**动态验证码**（给账号加第二把锁）：点 **生成密钥** → 用验证器 App（Google Authenticator / 1Password 等）扫二维码，扫码不便就手工输入下面那串**密钥** → 把 App 上显示的 **6 位动态验证码**填回来点 **绑定**。绑定之后登录要「密码 + 码」两步（见 [1.1](#11-登录)），登录页不用改什么，密码对了自会多出一格。要点：

- **绑定/解绑都要现码确认**：只拿到你一次密码的人绑不上、也解不了绑。
- **密钥加密存库**：库里存的是密文，界面上只在**生成那一次**显示明文密钥（之后再也看不到，也不会出现在任何日志与导出里）。解绑会把密钥一起清掉。
- **没有备用码，也没有自助恢复**（当前版本）：验证器 App 或手机丢了，**换手机之前先把新手机绑好**。解绑要求你当场交出动态验证码（在别的设备上登录着也一样），所以自助这条路走不通；「管理员管理」里的**重置密码也不会解绑**（防的正是「拿到重置权限就能接管开了 2FA 的账号」）。真丢了只能走**运维**：由有数据库权限的人在库层清掉该账号的 TOTP 列 —— `UPDATE admin SET totp_secret='', totp_enabled=0 WHERE id=<id>;`（`<id>` 是管理员在库里的**数字 id**，不是界面上的短串），清完用密码重新登录、再绑新设备；或者直接**恢复备份**（同 [5.1](#51-忘记超管密码了怎么办) 的超管口径）。

**登录设备**：一栏一台设备（浏览器标识、IP、登录时间、最近活跃），**当前这台**标着「当前设备」，其余的点 **踢出** 即可踢下线。每台设备有各自的令牌，踢出**只作废那一台**（改密码才是全部作废）；被踢的设备**下一次请求**就掉线（不是立刻，是下一次），它需要重新登录。

### 1.4 首页（仪表盘）

登录后第一屏是首页：一张欢迎卡（当前账号、昵称、是否超管、权限码数量、可访问菜单数），下面四张计数卡（**管理员 / 角色 / 部门 / 公告**），再下面是两张趋势卡：**近 7 天登录** 与 **近 7 天失败登录**，每张用 7 根柱子列出每天的次数（鼠标悬停显示那天的日期与次数；某天没有数据就是 0，整周都没有则显示「近 7 天暂无数据」）。首页**登录即可看**，不需要额外权限码；数字是全系统的汇总，不按数据范围过滤，也不含任何明细。

## 2. 权限体系怎么落地

一句话理解这套设计：

- **能点到什么 = 角色的菜单权限**（勾到按钮级）；
- **能看到哪些数据 = 角色的数据范围**（五档，见第 4 章）。

两者都挂在**角色**上，管理员通过挂角色获得权限。超级管理员（内置的 `admin`）不受这两套限制，他有一切权限、能看到所有数据。

推荐的落地顺序是 **先建部门 → 再建角色 → 最后建管理员**：

1. 部门先立好，后面角色的数据范围、管理员放在哪儿都要用它；
2. 角色把「能点什么 + 能看什么」定下来；
3. 最后建人，把人挂到角色上。

反过来做也能做成，但管理员要等角色建好才能挂上，中途组织结构一改就得返工。

### 2.1 第一步：建部门

菜单 **系统管理 → 部门管理**。部门是一棵可以无限分层的树。

1. 点 **新增** 建顶级部门，或某一行右侧的 **新增子部门** 往下挂。
2. 填 上级部门、名称、排序、负责人、联系电话、状态。
3. 删除有两条硬约束：**请先删除子部门**、**该部门下还有管理员**；另外也不允许把部门挂到自己的子部门下（防成环）。

部门**只影响数据范围**，不影响功能权限：一个人能不能看见「角色管理」菜单，和他属于哪个部门毫无关系。

「状态」目前只作标记：禁用的部门照样能被选进管理员表单、也算在「本部门及以下」的子树里 —— 别拿它当「关停部门」用。

### 2.2 第二步：建角色

菜单 **系统管理 → 角色管理**。

1. 点 **新增**，填 **角色名**（给人看的，如「部门主管」）和 **角色标识**（程序用的，3–64 位，只能用字母、数字、下划线、冒号，如 `admin`）。
2. 选 **数据范围**：五档之一，语义见第 4 章。
3. 保存后回到列表，点该行的 **权限** 按钮，打开「分配权限：xxx」抽屉，勾菜单。

抽屉里是一棵**菜单树**，三层：**目录 → 菜单 → 按钮**。

- 勾了某个菜单，侧边栏才会出现它；勾了菜单没勾按钮，进得去页面但看不到操作按钮。
- 按钮级节点会带 **（按钮）** 标记，例如「新增」「编辑」「删除」「重置密码」。
- 保存后立即生效，不需要任何人重新登录。

一个容易被绊到的点：这个抽屉打开时会**同时**加载菜单树和部门树，所以操作者除了角色的权限外，还需要 **菜单管理** 和 **部门管理** 的查看权限（`system:menu:list`、`system:dept:list`）——否则抽屉会因为拉不到树而打不开。给「只负责配角色」的人授权时记得把这两个查看权限一起给上。

### 2.3 第三步：建管理员

菜单 **系统管理 → 管理员管理**。

1. 点 **新增**，填 用户名、初始密码、昵称、部门、角色、状态。
2. 约束：用户名 3–64 位，只能用字母、数字、下划线，且不能重复；密码至少 8 位，且需包含字母、数字、符号中的至少两类；昵称必填（最长 64 字）。
3. **用户名创建后不能修改** —— 编辑表单里没有用户名这一项。密码也不在编辑里改，走 **重置密码**（或本人去个人中心改）。
4. 把用户名和初始密码告诉本人，让他登录后**立刻在个人中心改密码**。

**角色选择框**可以直接输入**角色名**过滤（多选自带搜索框）；一次最多列出 **100** 个角色，角色比这还多时下拉里会多一条「仅显示前 100 条，请在上方输入搜索」，照着输入名字筛出来即可。

关于「重置密码」和「启用/禁用」，有三个必须知道的后果：

- **重置密码**（管理员管理里对某一行的操作）会让该账号在**所有设备**上的登录立即失效，需要重新登录。这是安全设计，不是 bug，别忘了通知本人。
- **禁用**账号同理：所有在线会话立即失效，之后也无法登录。
- 系统有意设置了这几条硬规则：**不能删除超级管理员**、**不能删除自己**、**不能修改超级管理员的状态**、**不能修改自己的状态**、**不能重置其他超级管理员的密码**。

数据范围还管着「你能管谁」：

- 列表里看不见的管理员，你也改不到、删不掉，强行操作会被拒绝：**超出你的数据权限范围**。
- 新增/编辑时把目标放进你不负责的部门，同样会被拒。
- 给别人的**新增角色**也受约束：数据范围比你宽的角色（「全部数据」「本部门及以下」「自定义」）、以及带着你没有的权限码的角色，你都授不出去；这些角色在选择框里是**灰掉**的，提示「灰掉的角色超出你的数据权限，无法授予」。编辑时**只校验本次新增的角色** —— 别人手上本来就有的大权限角色不受影响，你照样能改他的昵称。
- 同一条规则也管着**角色的写入口**：数据范围比你宽（「全部数据」「本部门及以下」「自定义」）、或带着你没有的权限码的角色，你既改不了它的信息，也给它挂不了菜单、改不了自定义部门。反过来，**你给自己（或别人）的角色改数据范围，也只能落在「本部门」「仅本人」两档** —— 想把自己的角色调成「全部数据」这种加宽操作会被拒（提示与授权时同一条：**不能授予数据范围更宽的角色**）。

### 2.4 权限码长什么样、在哪儿看

权限码是**三段式**的字符串 `模块:资源:动作`，例如：

- `system:admin:list` —— 能看管理员列表；
- `system:admin:resetPwd` —— 能重置密码；
- `system:notice:edit` —— 能编辑公告（**发布 / 取消发布**也走这个码）。

看它的地方：**系统管理 → 菜单管理**。列表里有 **权限码** 列，每一行（包括每个按钮节点）都写着它的码；你在角色里勾的东西就是这些行。

内置的权限码全集只有下面这些（新建的库、没手工改过菜单时）：

| 菜单（侧边栏） | 权限码前缀 | 该模块已内置的动作 |
| --- | --- | --- |
| 管理员管理 | `system:admin` | `list`、`add`、`edit`、`remove`、`resetPwd` |
| 角色管理 | `system:role` | `list`、`add`、`edit`、`remove` |
| 菜单管理 | `system:menu` | `list`、`add`、`edit`、`remove` |
| 部门管理 | `system:dept` | `list`、`add`、`edit`、`remove` |
| 登录记录 | `system:loginlog` | `list`、`remove`（清空） |
| 操作日志 | `system:auditlog` | `list`、`remove`（清空） |
| 字典管理 | `system:dict` | `list`、`add`、`edit`、`remove`（字典项用同一组码） |
| 定时任务 | `system:job` | `list`、`edit`（改间隔、启停、触发一次） |
| 通知公告 | `system:notice` | `list`、`add`、`edit`、`remove` |

补充说明：

- 在 **菜单管理** 里可以自己新增菜单/按钮并填权限码，但**非超管只能填自己已有的码**：界面示例里的 `system:admin:add`，只要你手上没有这个码就会被拒（**没有权限：system:admin:add**）。若放开这条，等于允许「自己造一个码、再挂到自己角色上」的提权；超管不受此限。另外要注意：**新增的权限码只影响侧边栏显示和角色勾选**，不会让某个后端接口改变校验 —— 接口只认代码里写好的那些码。
- 侧边栏菜单之外的页面（首页、个人中心、顶栏的公告铃铛）不需要任何权限码，登录即可用。

### 2.5 前端藏按钮只是体验，后端每次都还会校验

这一条是理解整套权限的关键：

- **前端**会按你手上的权限码把按钮藏起来、把路由挡住。路由被挡住时你会看到 403 页：**没有权限访问该页面**，可以点 **返回首页**。
- **后端**才是真正管事的：每一个接口收到请求后，都会重新拿你**当前**的权限码校验一遍；缺权限的请求会被拒绝并提示 **没有权限**。所以「想办法让按钮重新出现」（改前端、直接调接口）并不会真的拿到权限。
- 权限是**每个请求实时算的**：停用角色、取消勾选菜单，下一个请求就生效，不需要重新登录。侧边栏菜单是登录时拉的一份缓存，刷新一下页面就能看到最新的；如果刷新后菜单项消失了，就是权限真的被收回了。

## 3. 各模块操作要点

### 3.1 管理员管理（system:admin）

列表按 用户名（模糊）和 状态 筛选，可以 **导出** 当前筛选结果；批量建号走 **导入**（见 [3.11](#311-csv-导入)）。新增时填用户名、初始密码、昵称、部门、角色、状态；**用户名和密码在编辑里不能改**（用户名创建后固定，密码走「重置密码」或本人去个人中心改）。行操作里有 **编辑**、**重置密码**、**删除** 和状态开关；重置密码和禁用都会把该账号的所有会话立刻踢下线。用户名、密码有长度与字符要求（3–64 位、字母数字下划线；密码至少 8 位，且需包含字母、数字、符号中的至少两类），不符合会当场报错。你自己看不见的管理员不会出现在列表里，也操作不了。列表上的 状态 切换到「禁用」，比删除温和，建议优先用它。

### 3.2 角色管理（system:role）

列表里的 **权限** 按钮打开分配权限抽屉（勾菜单树，到按钮级），第 2 章已经讲过。除菜单权限外，每个角色还有一档 **数据范围**，这决定它名下的管理员能看到哪些人的数据（第 4 章）。删除角色有条硬约束：**该角色已被管理员使用，不能删除** —— 先到管理员管理里把这个角色从所有人身上摘掉再删。角色标识（3–64 位，字母数字下划线冒号）不能重复。给角色勾权限、改数据范围都是即时生效的，改完在受影响账号那边刷新一下页面就能看到效果。非超管动手时，能改的只有**自己管得了的那类角色**：数据范围为「本部门」「仅本人」、且角色上挂的权限码是自己已有的子集（与第 2 章「能授出去」是同一条规则）；改数据范围也只能在这两档里改，给自己角色调成「全部数据」会被拒。

### 3.3 菜单管理（system:menu）

这里维护的是**侧边栏结构和权限码表**：一行就是一棵树上的一个节点，类型有三种 —— **目录**（可展开的分组）、**菜单**（点进去是一个页面）、**按钮**（不进侧边栏，只提供一个权限码）。表单字段：上级菜单、名称、类型、权限码、路由路径、组件、图标、排序、显示、状态。删除有两条约束：**请先删除子菜单**、**该菜单已被角色引用**（先把角色里勾的勾去掉）。**显示** 设为「隐藏」只是不在侧边栏列出来，不影响权限判定。另外：内置的这 13 个模块是每次启动自动补齐的，**删掉之后重启会重新长出来** —— 想彻底停用一个模块，用「隐藏」，或者不给任何角色勾它。

### 3.4 部门管理（system:dept）

一棵支持任意层级的部门树，每个节点可以 **新增子部门** 或编辑（上级部门、名称、排序、负责人、联系电话、状态）。删除约束：**请先删除子部门**、**该部门下还有管理员**；也不允许把部门挂到自己的子部门下。它只为数据范围提供坐标（第 4 章），不影响功能权限。组织调整时优先「改上级部门」挪分支，别删了重建——重建会换掉部门 ID，角色的「自定义」数据范围和已有管理员都会指空。批量建部门走 **导入**（上级部门按名称填、须已存在，见 [3.11](#311-csv-导入)）。

### 3.5 字典管理（system:dict）

左栏是 **字典类型**，右栏是选中类型的 **字典项**；没选类型时右栏是空的（会提示先在左侧选一个类型）。类型有 **编码**（就是取数用的键，只能小写字母、数字、下划线，2–64 位）、名称、状态；**编码创建后不可修改**（它是字典项的关联键），表单里会锁住并提示。字典项有 **标签**（下拉里显示的文字）、**值**（存库的值，同类型内不可重复）、排序、状态。删除字典类型会**连同它下面所有字典项一起删**（有二次确认），字典项也可以单独删。字典的用途是**给页面上的下拉框当数据源**：按类型编码取，只返回启用状态的项，改了立刻生效。需要说明的是：**后台自带的这几个页面目前还没有用到字典下拉**（菜单、角色这些下拉都是直接取树），这套数据源是留给业务页面用的——所以「建了字典但界面上没变化」是正常的。右栏的 **导出** 会把当前类型的字典项存成文件下载；同类型批量加项走 **导入**（见 [3.11](#311-csv-导入)）。

### 3.6 定时任务（system:job）

页面两个页签：**任务列表** 和 **执行记录**。任务列表顶部有句提示：「任务由代码注册（code 是注册键，库里只放调度与执行记录），这里只能改间隔与启停，不能新增或改名。」列表里能改 **间隔（秒）**、切换启停状态、点 **触发一次**。内置六个任务：**日志清理**（`log_retention`，按日志保留天数清理登录记录、操作日志、任务执行记录）、**头像孤儿清理**（`avatar_orphan_clean`，删掉已经没有任何管理员在用的头像文件）、**附件孤儿清理**（`attach_orphan_clean`，删掉附件中心里已经没有任何引用的文件，见 [3.14](#314-附件中心systemattach)）、**数据库备份**（`db_backup`，跑 `mysqldump` 把整个库备份到磁盘、只留最近几份，见 [5.10](#510-运维--数据库备份与恢复)）、**导出任务执行**（`export_run`，把导出中心里待处理的导出跑掉，见 [3.12](#312-导出中心systemexport)）和 **导出文件清理**（`export_clean`，删过期的导出记录与文件），除导出任务执行是 60 秒（每分钟，导出发起后不用等一整天）外，其余默认 86400 秒（1 天，界面上按天/小时/分钟/秒自动换算）。「触发一次」是**后台执行**：点完立即返回「已触发」，不占着页面等（数据库备份、大导出这类任务经常跑几分钟，等下去会撞上接口的 30 秒请求上限）。跑完列表的 **上次运行 / 上次结果** 会更新、**执行记录** 页签里多一条（含开始时间、耗时、结果、消息）—— 点完过一会儿刷新看，或到「执行记录」里等它出现。同一个任务**正在跑时再点会被拒**（提示「正在执行中，等这次跑完再触发」），不会叠出第二份同时在跑。状态显示 **停用** 的任务不再被调度，但「触发一次」照样能用——这是给运维临时停掉自动执行、需要时手动补跑留的口子。从未运行过的任务（新装、刚加进来）在服务启动后的第一个检查周期（10 秒内）就会跑一次。任务之间是排队串行执行的，一个跑得久会顺延后面任务的检查时间。 多实例部署时**只在一台开调度**（`[job] enabled = true`）—— 「正在跑就别再触发」的闸在进程内，不跨实例。

### 3.7 通知公告（system:notice）

新建的公告**一律先存成草稿**，界面提示「已保存为草稿，确认无误后再发布」；**草稿对普通用户完全不可见**（不会出现在任何人的未读里）。在列表里点 **发布**，它才会进入所有登录用户的顶栏铃铛；点 **取消发布** 会把它从大家的未读列表里撤掉（已读记录保留）。一个反直觉的细节：**发布时间只在第一次发布时写入**，之后取消发布再重新发布都不会刷新它 —— 所以一个草稿也可能已经有「发布时间」，看状态列为准。标题最长 128 字（表单里有提示），正文是纯文本，换行会原样保留。编辑弹窗里还有一栏 **配图**（上传即绑到这篇公告，新公告要先保存；权限与下载规则见 [3.14](#314-附件中心systemattach)）。删除公告会**连同所有人的已读记录一并删除**，确认框里有提示。用户侧：顶栏铃铛显示未读数，点开是「未读公告（n）」，每条能 **标记已读**；同时未读很多时只列出最近 50 条，列表底部会提示「还有 n 条未读，这里只列出最近 50 条。」

### 3.8 登录记录（system:loginlog）

每次登录尝试都会记一条（成功、失败都记），能看到 用户名、IP、时间、结果等，按条件筛选、**导出** 当前筛选结果（导**全量**用 [3.12 导出中心](#312-导出中心systemexport)，后台跑、不占页面）。**清空**：只会清掉**当前筛选条件下**的记录（确认框：「确认清空当前筛选条件下的登录记录？」），清完提示「已清空」；想全清就把筛选条件清空再点。这里的记录同样受数据权限约束：非超管只看得到自己数据范围内管理员的登录情况。

### 3.9 操作日志（system:auditlog）

记录所有**有副作用的操作**（新增、修改、删除类请求），登录页的登录请求不算（登录单独记在「登录记录」里）。列表显示 时间、操作人、模块、动作、请求、IP，按 用户名、模块、时间 筛选，支持 **导出**（导**全量**用 [3.12 导出中心](#312-导出中心systemexport)）与 **清空**（同样只清当前筛选条件，且**清空这个动作本身也会留下一条记录**，方便追溯是谁清的）。「模块」下拉里有 管理员 / 角色 / 菜单 / 部门 / 字典 / 系统配置 / 数据导入 / 导出中心 / 登录记录 / 操作日志 / 附件 / 认证 / 其他；定时任务、公告相关的操作在模块列会原样显示 `job` / `notice`，但下拉里没有这两项 —— 找这类记录时用用户名或时间来筛。日志里还可能看到动作是 **安全扫描命中** 的记录，见 [5.8](#58-操作日志里的安全扫描命中是什么)。

列表还有一列 **变更**：**编辑管理员 / 角色 / 部门 / 字典（类型与字典项）**时记下「改了哪些字段、旧值→新值」（只列真的变了的字段，格式如 `昵称: 旧名 → 新名`，多项用分号连接；导出 CSV 里是同一份 JSON 原文）。两条边界要记住：① 管理员的**邮箱 / 手机号是加密存储**的，摘要里只显示「已变更」，不落明文也不落密文（否则等于把落库加密抵消掉）；② **密码类接口**（重置密码、修改个人密码）**不产生摘要** —— 口令任何时候都不进日志，这类操作看动作名与时间即可。其余编辑入口（系统配置、定时任务、公告）目前不记摘要，动作名与请求路径照旧。

### 3.10 系统配置（system:config）

键值对形式的全局配置，按**分组**分卡片展示（现状只有一个「站点」分组）。每一项有：**配置键**（小写字母、数字、下划线，可点号分段，如 `site.copyright`；建成后不可修改）、**值**、**类型**、**分组**、**备注**（作为该项的标题显示）和 **公开** 开关——只有**公开**的键才会被登录页与页脚读取。操作要点：

- 每组右上角的 **保存** **只提交你改过的项**（一项都没改会提示「没有改动」），不会把整组重写一遍，也不影响别人同时改的其他项。
- 内置四个公开键：`site.copyright`（页脚版权文字）、`site.repo_url`（页脚项目地址）、`site.footer_enabled`（页脚是否显示）、`site.login_subtitle`（登录页标题下方的副标题，留空 = 不显示）。改完**登录页刷新即可见**；把页脚开关关掉，登录页与侧边栏都不再显示那一行。
- 前端**读不到**公开接口时（比如后端刚挂了）会回落内置默认值，页脚不会空着；页脚开关也只在**明确配置为「关」**时才隐藏，读不到不会误藏。
- **新增配置项** 默认**不公开**（要公开得手动打开开关）——避免手滑把内部参数发到登录页。键重复、键名不合法、类型不在 `单行文本 / 多行文本 / 布尔开关` 之内都会当场报错。
- 删除内置公开键后，对应位置回落内置默认值；**重启服务**时启动流程会把缺失的内置键补回来（已存在（含你改过的值）一律不动）。
- 布尔类型的值用开关控件编辑，存库是 `true` / `false` 字符串，经公开接口发给前端时转成真正的布尔值。
- 配好「通知设置」之后，这里会多出一个 `notify` 分组（见图 [3.13](#313-通知设置systemnotify)）。其中 **SMTP 口令那一项在本页看不到**：改它、删它都会被拒绝 —— 口令只从「通知设置」页的输入框进、只进不出，能在这页改它就等于把「加密存」变成摆设。

### 3.11 CSV 导入（管理员 / 部门 / 字典项）

管理员、部门、字典项三个页面的工具栏上都有 **导入** 按钮，流程一样：**下载模板** → 填好 → 上传 → 看逐行报告。三份模板表头各不相同，在哪个页面就用那个页面上的按钮下模板。

- **表头就是契约**：第一行逐字不能改（增删列、改字都会被拒，并提示应以的表头）。
- **部门 / 上级部门 / 角色 / 类型编码按名称或编码填**，且必须**库里已经存在** —— 导入不会顺手替你建。上级部门留空 = 顶层；角色多个用 `|` 分隔（如 `部门主管|人事专员`），留空 = 不分配。同一份文件里前面几行新建的部门**不能**当后面行的上级部门（先导入部门，再导入管理员）。
- **状态列**：`1` / `启用` / **留空**都是启用（跟页面上新增时的默认一样：不填 = 启用），`0` / `禁用` 才是禁用。要批量导**禁用**的账号/部门/字典项，这一列就得明确写 `0`。用户名、密码的长度与字符要求跟页面上**新增**时是同一套校验。
- **全有或全无**：只要有一行不合格，整批**一行都不写库**，弹窗里逐行列出「第 N 行 + 原因」；全部合格才在一个事务里一次落库。所以报告里出现红行时，这批数据在库里是找不到的 —— 改完文件整批重传即可。
- **不越权**：每一行都过发起人自己的权限与数据范围（部门超出范围、角色比自己宽，都会被逐行拦下），导入不是绕开这些规则的后门。按钮本身按各模块的**新增**权限码（`system:admin:add` / `system:dept:add` / `system:dict:add`）显隐，没有新增权限码。
- **编码只认 UTF-8**：Excel / WPS 另存时选「CSV UTF-8」（普通「CSV」是 GBK，会被拒并提示）。单次最多 5000 行；文件里只有表头、没有数据行时提示「没有可导入的数据」，不算失败。
- **长操作受 30 秒的请求上限约束**：接口层对所有请求有 30 秒超时（超时回 `request timed out`），管的是**返回响应之前必须算完**的那一段。导入正是这种路径（解析 + 落库都在这段里：几千行通常在秒级，行数越多这一口气就得越长）—— 几十万行这个量级别硬导，用 [3.12 导出中心](#312-导出中心systemexport)（后台跑，不受请求超时约束），或缩小筛选范围分次导。

### 3.12 导出中心（system:export）

后台导出：适合**数据量大、不想在页面等着**的场景（同步导出是点一下当场下载，页面上一直转圈）。侧边栏 **导出中心** 里选类型 → **发起导出** → 列表里看状态（待处理 / 执行中 / 已完成 / 失败），**已完成**的行点 **下载** 取文件。

- **导的是什么**：导出中心导的是该类型的**全量**数据（不受任何筛选影响）。要按条件导，去对应列表页点「导出」当场下载 —— 两边导出的**内容格式完全一样**（表头、转义、BOM 同一套代码），按条件导出来的文件同一个 Excel 里打开没差别。
- **谁来跑**：内置任务 **导出任务执行**（`export_run`，默认每分钟）把待处理的任务跑掉；列表在还有待处理 / 执行中的任务时**自动刷新**（3 秒一次），跑完自然停。急着要就去定时任务页对 `export_run` 点「触发一次」。**发起后一直停在「待处理」**多半是调度关了：`[job] enabled = false` 时 `export_run` 不会自动跑，手动触发它（或直接跑一次导出）照样能出文件。
- **保留期**：`[export] retain_days`（默认 7 天）。过了期由 **导出文件清理**（`export_clean`，每天一次）连**记录带文件**一起删（它同样依赖 `[job] enabled = true`；调度关了就去定时任务页手动触发 `export_clean`）；在过期前手动**删除**任务也会连文件一起删。所以文件别当长期归档用，要留就及时下载走。
- **权限两条闸**：能进导出中心要 `system:export:list`；发起某类型的导出还要有**那类数据**的查看码（操作日志要 `system:auditlog:list`，登录记录要 `system:loginlog:list`）。**导出中心是个人工作台**：列表只显示**自己发起**的任务，别人的记录看不见、下不了、删不掉（超管也一样）；`system:export:remove` 控制删除按钮。
- **数据范围按发起时的当前角色算**：任务真正执行时会用发起人**当时**的部门 / 角色数据范围重新算一遍（不是发起时的快照）——发起之后权限被收窄，还没跑完的任务也不会把已经看不到的数据导出去；发起人被删掉，任务直接失败并在消息列写明原因。
- **失败看得见**：失败的行「消息」列写着原因（未知类型、筛选参数损坏、写文件失败等），记录不会自己消失，删掉即可。

### 3.13 通知设置（system:notify）

「通知设置」把系统**对外发消息**的两个口子配好：**Webhook**（给外部系统推事件）与 **SMTP**（发邮件）。配置存在系统配置的 `notify.*` 键上（见 [3.10](#310-系统配置systemconfig)），**改完立即生效、不用重启**。

- **Webhook**：打开开关、填一个 `http://` 或 `https://` 开头的地址。有两个事件会 POST 一份 JSON 过去：**公告发布**（`notice.published`，草稿改成「已发布」的那一次；取消发布不发、已发布的公告改正文也不再发）与 **账号锁定**（`account.locked`，登录连续失败触发限流那一下，见 [5.2](#52-账号被锁了什么时候能再登)）。body 是 `{"event":"notice.published","at":1712345678,"data":{…}}`（`at` 是 Unix 秒）。单次请求 **5 秒超时**，失败**重试 3 次**（首发 + 3 次、间隔 500ms），**只把 2xx 当成功**，4 次都失败就放弃（只在服务端日志里留一行）。投递在**后台异步**做：对方服务器慢或者挂着，不会拖慢你发布公告、登录。
- **SMTP**：服务器 / 端口 / 加密方式（**STARTTLS** 常用 587、**SSL/TLS** 常用 465、**不加密**只适合本机联调）/ 用户名 / 口令 / 发件人。**口令加密存库**（AES-256-GCM）：页面上只是一个密码框，**留空 = 不改**、填了 = 换新，接口从不回显；**发件人留空就用用户名**，用户名也留空 = 不认证（本机 relay 场景）。
- **发测试邮件到我邮箱**：把测试信发到**你自己账号的邮箱**（先去个人中心把邮箱填对、并确认它能收信），用的是**已保存**的配置 —— 所以改完先点 **保存** 再点测试。成功提示收件地址，失败直接给原因（连不上 / 认证被拒 / 端口与加密方式不搭…），提示里不会出现口令。**开关没打开也能测**：先测通再打开是正常顺序。
- **谁能用**：能进这个页面要 `system:notify:list`；**保存** 与 **发测试邮件** 两个按钮要 `system:notify:edit`。
- 口令这一项到哪儿都**只进不出**：页面上不显示、审计只记「已变更」、日志与接口里都没有明文 —— 忘了就重填一把新的。
- 两类投递都**不是**「一定能到」：事件不落库、失败不重投（v1 取舍），要可靠投递请把接收端做成幂等 + 自己配监控抓服务日志。公告的**邮件**推送也没有做（只有测试邮件），要用就靠 Webhook 转发。

### 3.14 附件中心（system:attach）

通用的附件库。上传的文件先是**未绑定**的，之后可以**关联**到业务对象（v1 支持「公告配图」，见 [3.7](#37-通知公告systemnotice)）。页面里：**上传附件** → 列表（名称 / 大小 / 上传人 / 绑定 / 时间）→ **下载** / **关联** / **删除**；顶部可按 名称 与 绑定对象（未绑定 / 公告配图）筛选。

- **上传限制**（页面顶部有提示条）：单文件 **10 MB**，白名单里是 图片（png/jpg/gif/webp/bmp）、pdf、txt、csv、docx/xlsx/pptx、zip 共 13 种扩展名；**每个人**的总量受 `[attach] quota_mb` 约束（默认 200 MB，`0` 表示不限），超了会被拒绝并提示原因。
- **同一个文件只存一份**：内容相同（按 sha256 比）的文件重复上传不会在磁盘上再落一份，列表里是多行、盘上只有一份；**删到最后一行**引用时文件才真的删掉。
- **谁能下载**：绑到**已发布公告**的附件，任何登录用户都能下（公告配图，列表里标 **公开** 标签）；其余附件按**上传人的数据权限**判定 —— 上传人不在你的数据范围里，列表里看不到、也下不了。**关联** 与 **删除** 分别要 `system:attach:edit` / `system:attach:remove`；只有 `list` 的人能看能下，改不了关联、删不掉。列表里点 **关联** 打开弹窗选一篇公告即绑定（弹窗里**清空选择 = 解绑**）；下载入口在附件中心的 **下载** 按钮上，公告侧只能看到自己那几篇的配图。
- **在公告里配图**：通知公告的编辑弹窗里点 **上传配图**，绑定的是这篇公告（**新公告要先保存**，有了 id 才能绑）；配图行里可以挨个下载或删除。配图本身仍然住在附件中心，两处看到的是同一份文件。
- 附件被删、或者业务对象被删之后**没人引用**的文件，由内置任务 **附件孤儿清理**（`attach_orphan_clean`，每天一次）删掉，和头像孤儿清理一个机制（任务本身见 [3.6](#36-定时任务systemjob)）。

## 4. 数据权限：五档语义与验证方法

### 4.1 五档的确切含义

每个角色都要选一档 **数据范围**，界面上的名字就是下面这五个：

| 档位 | 界面名称 | 这个角色的管理员能看到的数据 |
| --- | --- | --- |
| 1 | 全部数据 | 不加任何限制，所有部门、所有人的数据都看得见 |
| 2 | 本部门及以下 | 自己所在的部门 **加上它的所有下级部门**（递归到底，含子部门的子部门），其它分支看不见 |
| 3 | 本部门 | 只限自己所在的这一层部门，**不含**子部门 |
| 4 | 仅本人 | 只看得见自己名下的数据 |
| 5 | 自定义 | 手工勾选的若干部门，可以是任意分支、可以跨层（在权限抽屉里勾） |

「数据范围」目前作用在四处：**管理员管理**的列表（按人所属部门过滤）、**登录记录** 和 **操作日志**（按记录所属管理员的部门过滤）、**附件中心**的列表（按上传人过滤；已发布公告的配图另按公开规则可下载，见 [3.14](#314-附件中心systemattach)）。菜单、角色、字典、公告属于全局配置，不按人分，能看到入口的人看到的是同一份。

两个要记住的边界情况：

- **没有部门的管理员**（部门选的是「（无）」）：选「本部门及以下」等于**什么都看不到**（「无部门」没有下级）；选「本部门」看到的也只是同样「无部门」的那部分人。要么给他挂个真实部门，要么用「全部数据」或「自定义」。
- **一个生效角色都没有**（没挂角色，或挂的角色全被停用）：也是**什么都看不到**。不是「默认给全部」，也不是「默认给本部门」。

### 4.2 怎么亲手验证（两角色两管理员对比列表条数）

准备：在 部门管理 里建三个部门 —— **甲部**、**甲部-一组**（甲部的子部门）、**乙部**；在 管理员管理 里建三个测试账号：

| 账号 | 所属部门 | 说明 |
| --- | --- | --- |
| `u1` | 甲部 | 验证对象 |
| `u2` | 甲部-一组 | 甲部的下级 |
| `u3` | 乙部 | 甲部之外的分支 |

再建两个只用于对比的角色（各自只勾 **管理员管理** 的 `list`，别的都不勾，方便看差异）：

- 角色「部门主管」：数据范围 = **本部门及以下**；
- 角色「全局主管」：数据范围 = **全部数据**。

然后：

1. 把「部门主管」挂到 `u1` 身上，用 `u1` 登录，进 **管理员管理**。列表里只有 **甲部及其下级** 的人（`u1`、`u2`，加上他自己）——`u3`、超管、以及其它部门的人都看不到。记下列表底部的总条数。
2. 用超管登录，把 `u1` 的角色改成「全局主管」，让 `u1` 刷新页面再看：条数变多，`u3` 出现了，超管也出现了。
3. 想验证 **仅本人**：再建一个角色，数据范围选「仅本人」（不需要勾菜单权限以外的任何东西），挂到 `u1` 身上，`u1` 刷新后列表里只剩他自己一条。
4. 想验证 **自定义**：建角色「甲乙主管」，数据范围 = **自定义**，在权限抽屉的部门树里**只勾「乙部」**，挂给 `u1`；`u1` 刷新后能看到乙部的 `u3`，但看不到甲部-一组的 `u2`。

观察到的差异只在**列表条数**上，按钮和菜单不会变（功能权限和数据范围是两回事）。整个过程不需要重新登录，改完刷新页面即可；对比条数时注意筛选条件要一致（都留空）。

### 4.3 一个人有多个角色时怎么算

可以给一个人挂多个角色，两套东西都是**取并集**：

- **功能权限**：所有**启用**角色勾过的权限码合在一起，能点的按钮就是这些码的并集。
- **数据范围**：所有启用角色的部门范围合并去重；只要其中**任意一个**角色是「全部数据」，结果直接就是全部数据（最高优先级）；只要其中**任意一个**角色是「仅本人」，就在部门范围之外**额外**加上「只看自己」。最终效果 = 几个角色各自能看到的范围加起来，只多不少。
- **停用的角色完全不参与**：既不给功能权限，也不给数据范围。
- 所以「给他加个角色」永远是放宽；要收窄，得先把宽的角色摘掉。

## 5. 常见问题

### 5.1 忘记超管密码了怎么办

超管密码**只在首次启动**（管理员表为空的那一次）按配置里的初始密码写入一次。之后改配置文件、重启服务都不会影响已经存在的账号，所以「改配置再重启」这条路是不通的；密码在库里也是加密哈希，翻不出原文。

界面上同样没有找回入口——系统有意禁止重置超级管理员的密码（「不能重置其他超级管理员的密码」），正是为了不让任何人借「重置」这条路接管超管。

实际可行的只有两种：

- 你还**登录着**超管（比如浏览器没退）：直接去 **个人中心 → 修改密码** 改掉它。
- 已经登不进去了：这属于运维动作，需要能碰服务器的人侧处理（按部署文档在数据库层面重置，或从备份恢复）。注意：清空管理员表能让系统在下次启动时重新写入初始超管，但**所有管理员账号会一起丢失**，不到万不得已不要这么做。

防患于未然：拿到初始密码后第一件事就是去个人中心改掉，并记进密码管理器。

### 5.2 账号被锁了，什么时候能再登

「尝试过于频繁，请 N 分钟后再试」是登录限流触发的，默认连续 **5** 次密码错误就锁 **10** 分钟。要点：

- 触发维度有**两个**：同一个账号、同一个来源 IP（同一出口 IP 下的人可能互相「带累」）。
- **验证码答错不计入**失败次数，只有密码错才算。
- **解锁方式就是等**：窗口过去自动解除。成功登录会清掉该账号的失败计数；来源 IP 的计数要等窗口到期。
- 计数保存在服务进程的内存里，所以**服务重启会立刻清空**。
- 阈值本身是可配置项（失败次数、锁定时长），部署方可以按需要调；这两个值都设成 0（或负数）等于关闭限流。
- 锁定的那一刻，如果配了 Webhook，会给接收端推一条 `account.locked`（哪个账号、来源 IP、解锁时间，见 [3.13](#313-通知设置systemnotify)）。

### 5.3 语言和主题在哪里改，为什么换了台电脑就变了

都在顶栏：**切换语言**、**切换明暗主题**。它们只保存在你这台电脑的浏览器里，不跟账号走——换设备、换浏览器、清浏览器数据之后都会回到默认（语言跟随浏览器、主题跟随系统）。

### 5.4 头像传不上去

按提示对症处理：

| 现象 / 提示 | 原因与处理 |
| --- | --- |
| 图片读取失败，请换一张 PNG/JPEG | 选的文件不是 PNG/JPEG（改了后缀的也不行），换一张真图 |
| 压缩后仍超过 512KB，请换一张小一些的图片 | 浏览器自动压缩后仍然超过 512 KB，换一张尺寸更小的图 |
| 头像不能超过 512 KB | 服务端硬上限拦截，同上，换小图 |
| 头像上传失败 | 网络中断或服务不可用，重试一次；持续失败找管理员看服务状态 |

别忘了上传过程中有进度显示，大图（接近 512 KB）在慢网络下要等几秒，别急着关页面。

### 5.5 公告发布了，为什么有人看不到

按顺序检查：

1. **它还是草稿吗**？列表里状态为「草稿」的公告对普通用户**完全不可见**，必须在列表里点 **发布**。
2. 对方看错地方了吗？未读提示在**顶栏铃铛**里，不在侧边栏菜单里。
3. 是不是已经被 **取消发布** 了？取消发布后它会从所有人的未读里消失（已读记录还留着，重新发布不会重复提醒已经读过的人）。
4. 铃铛里一次只列**最近 50 条**未读，如果对方积压了很多条，旧的那条可能没显示出来，列表底部会提示「还有 n 条未读」。

### 5.6 定时任务为什么没跑

依次排查：

1. **调度开关**：部署配置里 `[job] enabled` 为 `true` 时，服务才会启动调度循环。它被关掉时，**自动调度完全停摆**，但手动 **触发一次** 仍然可用——先用「触发一次」确认任务本身没问题。
2. **任务状态**：列表里显示 **停用** 的任务不会被调度（但上面说了，仍然可以手动触发）。
3. **间隔没到**：任务按「上次运行时间 + 间隔」判定，间隔单位是**秒**；列表里的「间隔（秒）」和「上次运行」可以直接对。
4. **从来没跑过**：新装或新加的任务「上次运行」显示 **从未运行**，服务起来后第一个检查周期（10 秒内）就会补跑一次；如果一直没跑，回到第 1、2 条。
5. **跑了但失败**：「执行记录」页签里看每次执行的 结果 和 消息（列表的「上次结果」也写着最后一条结果）。任务失败不会重试，等下一个间隔再跑。

### 5.7 升级后为什么要重新登录

登录令牌里带了一个**版本号**。服务端**每次请求**都会拿它和账号上的版本号比对，对不上就判定为失效——界面表现是跳回登录页，提示「登录已失效，请重新登录」。

会让版本号变动、从而让**所有已签发的旧令牌立即作废**的操作有：

- **退出登录**、**退出其他设备**；
- **修改密码**、**被管理员重置密码**；
- **账号被禁用**。

所以「升级后要重新登录」通常不是升级这个动作本身造成的，而是上面某件事（或者升级时顺手换掉了签名密钥）的结果。重新登录一次即可，数据不受影响。反过来看，这也是为什么重置别人密码之后要记得通知他：他会被立刻踢下线。

### 5.8 操作日志里的「安全扫描命中」是什么

那是请求安全扫描的记录：服务会对每个请求做一遍攻击特征检测（SQL 注入、命令注入、路径穿越、SSRF 之类），命中的请求会在 **操作日志** 里留下一行，模块是 `security`、动作是 **安全扫描命中**。

关键点：

- **默认只记录、不拦截**：默认配置下命中的请求照常执行，只是留一条痕。这是有意的——误报真实存在（密码里带 `' or 1=1--` 的用户名、公告里贴的代码片段），直接拦会误伤正常工作。
- 部署方可以把扫描调成「命中高危就拦截」；那种情况下被拦的请求会直接返回失败（提示 **请求被安全策略拦截**），日志里那行的结果会是失败——这时候用户在界面上看到的是操作没成功，而不是「服务坏了」。
- 日志里**只记等级和检测器的名字，不记请求的原始内容**，所以别指望从这行里翻出对方到底发了什么；真要追查，结合同一时间的其它日志一起看。

### 5.9 运维 · 清理明文备份

这一条给能碰数据库的运维看，普通使用者可以跳过。

表 `admin_email_phone_backup` 是 email / 手机号**存量加密迁移**留下的**明文备份**：迁移把库里原有的明文字段逐行加密回写，写之前先把**原值**存进这张表 —— 密钥一旦丢了或换错，密文就解不开了，这是唯一的退路。反过来说，只要它还留着，**明文 PII 就一直敞在库里**，确认不需要了就该清掉。

**清理前必须验证**：当前密钥能正常解密。登录后打开 **个人中心**，邮箱、手机号要显示**原文**（能正常读写即解密正常）。看不到原文就不算验证过 —— 页面能打开、显示空白或脱敏值都不能证明密文解得开。

还要看一眼**启动日志里有没有「加密失败，暂留明文」**：服务每次启动都会把存量明文逐行加密，个别行搬不动（比如密文撑爆列宽）就留在原处、日志点名、下次启动再试。出现过这一行就说明**库里还有明文行** —— 那行没搬完之前先别清：清了备份表，下次启动又会把它重新写进（新建的）备份表。

验证通过、且升级后确定不需要回滚了，就可以清理（**不可逆**，清完没有任何回退手段，密钥再丢就真的找不回了）：

```sql
DROP TABLE admin_email_phone_backup;
```

建议清之前先把表导出一份留档，存进密码管理器或离线位置：

```bash
mysqldump bee_admin admin_email_phone_backup > admin_email_phone_backup.sql
```

服务每次启动都会数一下这张表的行数，还有数据就在日志里 warn 一行提醒；清掉之后提示自然消失。

**清完表又冒出来（空表）是正常的**：启动迁移里有 `CREATE TABLE IF NOT EXISTS`，删掉的表会在下次启动时以**空表**重建 —— 空 = 清理成功，别当成没清掉；只要行数是 0，就没有明文留在库里。

### 5.10 运维 · 数据库备份与恢复

这一条也是给运维看的。内置任务 **数据库备份**（`db_backup`）把整个库用 `mysqldump` 导到磁盘上，默认每天跑一次。要点：

- **落在哪**：`[backup] dir` 指定的目录；不配就落在 `{upload_dir}/backups/`（默认即 `uploads/backups/`）。文件名形如 `backup_20261016_030000.sql`，**权限 0600**（dump 里是全库数据，包括口令哈希，别改成同机可读）。
- **留几份**：`[backup] keep`，默认 7 份；每跑完一次就删掉多余的**最旧**备份。`keep` 必须是 ≥ 1 的整数，配成 0 或负数服务会**拒绝启动**（等于每跑一次就把备份全删了）。
- **怎么立刻备一份**：定时任务页里对 **数据库备份** 点 **触发一次**（立即受理、**后台执行**，不占着页面等），到 **执行记录** 页签里看这次跑的耗时与消息（含文件名和字节数）。
- **任务失败不算接口失败**：跟其它任务一样，结果看执行记录里的 `status` 与 `msg`（常见原因：`mysqldump` 没装、DNS 里的账号密码不对、磁盘满）。
- **恢复是手工动作**（不做自动恢复，避免误触发覆盖现网）：先在库里确认要恢复的 dump 文件，然后

  ```bash
  # 1) 停服务（别带业务写入做恢复）
  sudo systemctl stop bee-admin
  # 2) 恢复（口令走环境变量，别进命令行历史）
  MYSQL_PWD='口令' mysql -h 127.0.0.1 -u 用户 bee_admin < /path/to/backup_20261016_030000.sql
  # 3) 起服务
  sudo systemctl start bee-admin
  ```

  恢复会按 dump 里的 `DROP TABLE IF EXISTS` + `CREATE TABLE` **覆盖同名表**，库里 dump 之后的新数据会没掉——这就是要先停服、想清楚的原因。恢复完照常登录（账号数据也来自 dump，用当时的密码）。
- `mysqldump` 用的连接参数就是从 `[db] dsn` 里拆出来的（同一份凭据），所以备份能不能跑通可以直接用 `mysql` 客户端拿同一组参数试。

### 5.11 通知没发出去 / 测试邮件失败

- **Webhook 没收到**：先看开关和地址（必须是 `http://` / `https://` 开头，保存时就会拦）；再看接收端要求 —— 我们发的是 `POST` + `Content-Type: application/json`，body 是 `{"event","at","data"}`。接收端回非 2xx、或者 5 秒没响应，都算**一次失败**并重试，最多 4 次（首发 + 3 次重试）后放弃。
- **事件不会补发**：事件不落库，失败只在**服务端日志**里有一行。所以「对方服务器重启那 2 分钟里的事件」是收不到的 —— 要补，请在接收端自己留请求日志（我们重试的 4 次你都会看到，按 `event` + `at` 去重即可）。
- **测试邮件失败**：提示里就是原因。常见的几条：`connection refused` / 超时（主机名或端口不对，或对方只在内网通）、`authentication failed`（用户名 / 口令不对，或者服务商要求用**应用专用密码**）、证书相关报错（加密方式选错了：465 用 **SSL/TLS**、587 用 **STARTTLS**）、`sender address rejected`（发件人不是服务商允许的地址 —— 多要求发件人 = 认证账号）。**测通了记得把 SMTP 开关打开**，测试邮件本身不看开关。
- **收件箱里没有**：先翻垃圾邮件 / 已过滤；再把发件人换成服务商允许的地址重试一次。
