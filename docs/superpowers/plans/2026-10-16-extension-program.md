## 执行纪律（每个实现者都要遵守）

- **单写者**：同一时间只有一个 agent 在本仓库干活（git 与 cargo 都不能并发写）；
  在 `ext-<项号>` 分支上提交，**不 push**，由负责人（lead）复核后合入 main。
- 改动的优先面是 `admin/`（后端 + `admin/web`）与 `docs/`；**`crates/` 是本仓 vendored
  框架副本，允许漂移但尽量不动**，确需动先在提交信息里说明理由。
- 新依赖要写理由（现有依赖能做的用手写的）；延续「无必要不加库」的口径。
- 每项都要：单测 + 能真跑的验证（本机 MySQL，`admin/conf/app.conf` 的 dsn 换库名
  `bee_admin_test` 即可；没设 DSN 的集成测试会静默跳过 = 假通过，注意别被骗）。
- 新模块/新接口要同步：种子权限码 + 菜单、`audit_log` 留痕（有副作用的写路径）、
  前端 i18n 中英两套、README 功能介绍表与接口计数（会在批次末尾统一核一遍）。
- 前端沿用现状：antd 5 + React 18，**不引图表库**（迷你趋势手绘 SVG），
  新依赖仅限能力刚需（如 TOTP 二维码）且要论证。

## 每项范围与验收

### A1（11）`/api/v1/version` 版本接口
- 后端：`GET /api/v1/version` → `{version}`。版本源 = 构建时注入（build.rs 读
  `BRA_VERSION` 环境变量，release.sh 已在用这个名字；没注入回落 `dev`）。
- 验收：`BRA_VERSION=vX curl` 本地构建后接口回 `vX`；未注入回 `dev`；接口计数 64→65 同步。

### A2（12）`/metrics` 指标端点
- Prometheus 文本格式，手写（不引库）：进程启动时间、请求总数、按状态码分类计数、
  每接口计数与延迟直方图（简单 bucketed，AtomicU64 即可）。
- 鉴权：**不加**——服务只监听 127.0.0.1，公网由 nginx 决定转不转；文档写明。
- 验收：curl 有合法文本；打 20 个请求后计数对得上。

### A3（1）系统配置模块（sys_config）
- 表 `sys_config`（key / value / 类型 / 分组 / 备注）；权限码 `system:config:view|edit`；
  菜单「系统配置」；种子给默认值。
- v1 键集（都对应现在写死的值）：页脚版权文字、页脚项目地址、页脚是否显示、
  登录页副标题；`GET /api/v1/configs/public`（**免登录**，只回标记为公开的键）供
  登录页/页脚读取；管理端 CRUD + 分组列表。
- 前端：「系统配置」页（分组表单）；页脚（SiteInfo）改为读公开配置（拿不到就回落到
  现在的内置值——离线/接口挂了不能空着）。
- 验收：改配置 → 登录页/页脚刷新即变；public 接口不泄露非公开键（负控）；权限码生效。

### A4（2）真仪表盘
- `GET /api/v1/dashboard/stats`（登录即可，计数不含敏感数据）：管理员/角色/部门/公告
  数与近 7 天登录次数（按天）、近 7 天失败登录数。
- 前端：计数卡 + 手绘 SVG 迷你趋势 + 空态；沿用现有欢迎卡的信息。
- 验收：造数据后数字与 SQL 对得上；无数据时不炸。

### B1（9）备份
- 内置任务 `db_backup`（走既有定时任务注册模式）：解析 `[db] dsn`（复用 install.sh
  的 urlenc 教训）→ `mysqldump` → 落 `uploads/backups/`（目录可配）→ 保留最近 N 份
  （默认 7）→ 手动触发一次 + 执行记录（复用 job_log）。
- 恢复：不做自动化，写清楚文档（`mysql < dump` + 停服顺序）。
- 验收：真跑一次，dump 文件非空且能被 `mysql --help` 级校验（读头部）；保留策略删旧。

### B2（3）CSV 导入（管理员 / 部门 / 字典项）
- 模板下载（复用导出通道的思路）+ 上传 → **单事务全有或全无** → 逐行校验报告
  （行号 + 原因，成功/失败都回显）。
- 解析：可引 `csv` crate（理由：引号/换行/编码的正确性，手写不值）；导入前过现有
  校验函数（密码策略、权限子集等**复用**，不许另写一套）。
- 验收：正常样例全绿；含坏行的样例整批回滚 + 报告逐行指出；权限/数据范围不越权。

### B3（4）异步导出
- 表 `export_task`（谁、导什么、参数、状态、文件、过期）+ 「导出中心」页（列表/
  下载/删除）；执行挂在既有 job 循环；首批 kind：操作日志、登录记录（复用现有同步
  导出逻辑，抽公共层）。
- 验收：发起 → 任务跑完 → 文件可下、内容与同步导出一致；过期清理生效。

### C1（8）审计差异（before/after）
- `audit_log` 增记变更摘要（JSON：改了哪些字段、旧值→新值）；在**写 handler 内显式
  记录**（通用中间件拿不到旧值），首批铺 admin/role/dept/dict 四个模块的 update。
- 敏感字段（密码/密钥类）**永不出现在摘要里**（负控测一条）。
- 验收：改一条管理员昵称 → 审计里能查到 旧→新；改密码 → 摘要里无密码字样。

### C2（7）TOTP + 登录设备
- TOTP：admin 表加列（secret **加密存**，复用 AES 设施）；profile 页绑定/解绑
  （otpauth URL 二维码——前端可加轻量 `qrcode` 依赖，理由：绑定体验刚需）；登录时
  已绑定则要求验证码；备用码 v1 不做（文档写明）。
- 设备列表：登录时记 `admin_login_device`（设备指纹/IP/最后活跃）；profile 页列出 +
  踢单台（与既有 token_version 全量作废分开）。
- 验收：真机绑定（用任意验证器算法自校验：HMAC 结果与已知向量一致的单测）→ 登录要码；
  错码拒绝；踢设备后该设备下次请求 401。

### C3（6）通知渠道
- v1：**Webhook**（事件：公告发布 / 账号锁定 → POST JSON，超时+重试 3 次，配置走
  sys_config）+ **SMTP**（配置页含「发测试邮件到我邮箱」按钮；公告发布邮件推送放 v2）。
- 邮件库可引 `lettre`（成熟）；SMTP 口令加密存、日志不打码。
- 验收：本机起个假 webhook（nc/临时 HTTP）收到事件体；SMTP 测试按钮给出成功/失败原因。

### D1（5）附件中心
- 表 `attachment`（上传人、原名、类型、大小、sha256、存储路径）+ 多态绑定
  （entity_type/entity_id + 排序）+ 下载鉴权（登录 + 数据权限约束）+ 类型/大小白名单 +
  配额（每人总量上限，可配）。
- 复用头像分片上传的落盘/校验经验；公告配图作为第一个消费者（可选，给验收用）。
- 验收：上传/列表/下载/删除全链路；越权下载被拒（负控：别的角色拿不到非公开附件）。

### D2（10）模块脚手架
- `scripts/scaffold-module.sh`：输入 模块名/权限前缀/字段清单 → 生成后端
  api+model 骨架、单测骨架、前端 page+api 封装、i18n 占位、菜单种子 SQL 草案；
  生成物**必须自己先编译通过**（脚本末尾跑 `cargo check` + `tsc`）。
- 验收：生成一个新模块 → 编译绿 → 按文档手工补两口即可跑（用一个真例子演示：
  比如用脚手架重造「字典管理」的骨架与现有代码对照）。
- 文档：`docs/scaffold.md`（这是唯一允许新建的说明文档）。
