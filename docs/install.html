BRA 安装引导

Bee Rust Admin —— Rust 后端 bee_admin + React 前端 dist + MySQL 8 + nginx。 这一页给部署者：讲清怎么装，并当场生成一份填好的 app.conf。

1前置要求

  • Linux x86_64（ARM 只能从源码构建或用 Docker）
  • MySQL 8.0+，字符集 utf8mb4
  • root 或 sudo —— 只有装 systemd 单元 / nginx 站点那一步需要，其他步骤普通用户即可

⚠️ 最要紧的一条：glibc 版本。预编译二进制需要 glibc ≥ 2.38 （= Debian 13 / Ubuntu 24.04 及以上）。Ubuntu 22.04（2.35）、Debian 12（2.36）、CentOS 上会直接报 version 'GLIBC_2.38' not found，二进制根本跑不起来。

ldd --version | head -1     # 末尾数字就是 glibc 版本

低于 2.38 就分叉：改用「从源码构建」（--mode build）或「Docker」， 别看下面的一键脚本了。

补充：install.sh 自己会检测这件事 —— 它会让下载来的二进制真的加载一次， 跑不起来就在写盘之前退出，并给出上面这两条替代命令，不会留下一个装了一半、 又起不来的安装。

2配置生成器

填好下面几项，右边/下面的 app.conf 实时更新，点「复制」拿走即可。 不填的项保持默认。

三样密钥（encrypt_key / hashids_salt / [jwt] secret） 以及上面的口令，都只在这个页面本地生成（浏览器 crypto.getRandomValues 算的）， 不上传、不保存、不联网。
⚠️ encrypt_key 与 hashids_salt 生成后不可更换： 换 encrypt_key = 库里已加密的 email/phone 永久解不开； 换 hashids_salt = 已发出的对外短 id 全部作废。生成完就把这份 conf 备份好。

3三种装法

(a) 一键脚本 推荐

下载后跑，别直接 curl | bash —— 这个脚本要 root 装 systemd 与 nginx，值得先看一眼：

curl -fsSLO https://raw.githubusercontent.com/erikwang2013/bee-rust-admin/main/install.sh
less install.sh          # 先看一眼（脚本要 root 装 systemd/nginx，值得看一眼）
bash install.sh          # 交互式：会问数据库口令

它依次做：拉发布产物（二进制 + 前端 dist）→ 生成密钥 → 写 <prefix>/conf/app.conf（0600）→ 建库（可选）→ 装 systemd 单元 + nginx 站点 → 起服务并自检 /api/v1/health。默认装到 /opt/bee-admin，对外 8081。

建库是可选的：给 --db-admin-user U --db-admin-pass P 它才自动建库建号； 不给就只打印 SQL 让你手工执行（它不猜 root 口令、不 DROP、不装 MySQL）。 表结构与超管账号由服务首次启动时自动创建，不需要手工导 SQL。

常用变体（参数名照 install.sh --help 写）：

# 老机器（glibc < 2.38）：从源码构建（需要 rust 1.99+ / node 20+ / pnpm 9+）
bash install.sh --mode build

# 装第二套实例（目录、服务名、端口、雪花节点全错开）
bash install.sh --service-name bee-admin-2 --prefix /opt/bee-admin-2 \
                --http-port 8091 --backend-port 8090 --snowflake 2,0

# 先看会做什么（不落盘、不下载、不连库）
bash install.sh --dry-run --yes

# 升级：只换二进制与服务文件，配置一个字节都不动（后面的 ... = 照旧带上你原来的参数）
bash install.sh --keep-conf ...

已经有 app.conf 时，脚本默认拒绝覆盖（退出码 6）—— 因为 encrypt_key 一换，库里已加密的 email/phone 就永久解不开。 要覆盖得显式加 --force：它会先把原文件备份到 app.conf.bak.<时间戳>，但换了密钥之后数据仍可能解不开 —— 只有明确知道后果才用它。 正常升级走 --keep-conf。

(b) Docker compose

仓库里已备好 docker-compose.yml（MySQL + 后端 + 前端三件套，对外 8081）：

cp .env.example .env && vi .env                      # 填 MySQL root 密码
cp admin/conf/app.conf.example admin/conf/app.conf   # 填 jwt secret / encrypt_key
docker compose up -d --build
# 打开 http://localhost:8081（初始账号 admin / 配置里的 initial_admin_password）
  • 容器内的数据库地址由 BEE_ADMIN_DB_DSN 注入（指向 compose 里的 mysql 服务）； 配置文件仍从宿主机 admin/conf/app.conf 挂载进去，JWT secret 与初始口令从那儿读
  • 后端容器以「宿主机配置文件属主」的身份运行（.env 里的 APP_UID/APP_GID，默认 1000:1000）： app.conf 常是 600 权限，用镜像默认的非 root 用户会读不到配置而启动失败。 你的宿主 uid/gid 不是 1000 就得在 .env 里改（id -u / id -g 查）
  • 想接已有的 MySQL：删掉 compose 里的 mysql 服务与 depends_on，改 BEE_ADMIN_DB_DSN 即可

(c) 手工部署

systemd 托管后端（监听 127.0.0.1:8080）+ nginx 对外 8081：

cargo build --release -p bee_admin
cd admin/web && pnpm build

sudo cp admin/deploy/bee-admin.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now bee-admin

# 站点目录按自己的 nginx 来：自编译版常在 <prefix>/conf/vhost/，发行版在 /etc/nginx/conf.d/
sudo cp admin/deploy/nginx.conf.example /usr/local/nginx/conf/vhost/bee-admin.conf
sudo nginx -t && sudo systemctl reload nginx

admin/deploy/ 里那两个文件里的路径与用户名是示例 （写的是 /home/wwwroot/bee-rust-admin 和 erik）， 要按自己的改成实际值 —— 或者直接用 install.sh，它会按实际路径 / 用户 / 端口渲染。

4装完自检 + 常见坑

后端（端口 = 上面填的后端监听端口）：

curl http://127.0.0.1:%BE%/api/v1/health     # => OK

然后浏览器打开（端口 = 对外端口）：

http://<这台机器的地址>:%HTTP%

用 admin + [seed] initial_admin_password 登录，登录后立刻改密码。

常见坑

  • app.conf 是 600 权限：跑服务的用户必须是它的属主，否则起不来； 容器里则要对上 APP_UID/APP_GID。
  • encrypt_key 不可更换：换 = 库里 email/phone 永久解不开（没有救援）。备份它， 连同整份 app.conf 一起。
  • hashids_salt 一换，已发出去的对外短 id 全部作废。
  • 初始口令只在库为空时生效：库里已有 admin 就忽略它，得登录后在后台改。
  • 前后端要一起换：升级时后端删了旧的 base64 头像接口，老前端配新后端会在头像上传上报 404。
  • 验证码默认开（[auth] captcha = true）：登录要多点一下；答错不计入锁定次数。
  • 仓库根目录的 install.sql 与本项目无关（那是另一个工具的库），安装不需要它。
  • 忘了超管密码：改库里的 admin 表（或重建库重来）。
